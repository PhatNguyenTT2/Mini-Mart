Rights statements below describe the observed primary-source record, not legal advice. PENDING is intentional whenever primary evidence does not distinguish a right. Repository code licenses do not automatically license bundled or upstream data. “Model-output rights” remains separate because neither a permissive data license nor permission to research automatically decides whether a particular output reproduces protected text, identifiers, or licensed expression.

## Decision vocabulary

| Value | Meaning |
|---|---|
| ALLOWED | Primary terms expressly support the use, subject to their conditions. |
| CONDITIONAL | A primary term supports some use, but another applicable term, content class, or access contract requires E5 review. |
| PROHIBITED | Primary terms expressly disallow the use absent separate permission. |
| NOT_STATED | The reviewed primary source does not address the field. |
| PENDING | Terms, current access contract, provenance, or legal classification are missing or unresolved. |

## Access and rights gates handed to E4/E5

1. Acquire only assets admitted by E1/E3 and only through the canonical route recorded above. Do not use mirrors as a substitute for missing provider permission.
2. Record the access-time terms or license, final resolved URL, filenames, byte sizes and SHA-256. Where a provider publishes MD5, retain it as a provider checksum and also compute SHA-256.
3. Keep TEST assets unopened. A competition download containing test files must be quarantined and inventoried without opening until the registered gate authorizes access.
4. For processed repository packs, bind the exact Git commit and prove raw-provider-to-processed-file lineage. A Git hash establishes identity, not lawfulness.
5. E5 must issue separate determinations for research, commercial use, redistribution, derivative artifacts, model outputs and privacy. No PENDING cell is silently promoted.
